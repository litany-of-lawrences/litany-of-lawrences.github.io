Implementation approaches

How should the tree be built and rendered?

A

D3.js force / tree layout

Use D3's built-in tree layout algorithm. Handles arbitrarily complex graphs automatically and produces smooth animations. Well-tested, lots of prior art for genealogy trees.

Pros

  • Automatic layout
  • Smooth transitions
  • Handles edge cases well

Cons

  • ~87KB external dependency
  • Overkill for a focused-person view
  • D3 API is complex
B

Custom SVG layout (recommended)

Parse relationships at build time into a JSON data file. Render focused-person view in SVG with vanilla JS: parents in a row above, the focused person centred, children in a row below. Click re-centres with a smooth transition.

Pros

  • No dependencies
  • Fits the site's aesthetic
  • Exactly as complex as needed
  • Easy to style with site SCSS variables

Cons

  • Manual layout logic
  • Siblings not shown (only parents + children)
C

HTML Canvas

Draw the tree on a canvas element. More control over rendering, supports pan/zoom natively.

Pros

  • Pan and zoom built-in
  • Handles very large graphs

Cons

  • Canvas is not accessible
  • Much harder to style consistently with the site
  • Links/hover states require manual hit-testing
