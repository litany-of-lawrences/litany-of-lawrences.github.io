# GitHub Pages Wiki — Design Spec

**Date:** 2026-03-24
**Project:** Litany of Lawrences
**Scope:** Sub-project 1 of 2 — static wiki site (desktop editor app is a separate sub-project)

---

## Overview

A static wiki site built with Eleventy and deployed to GitHub Pages. It publishes the family history articles generated by `parse_docx.py` and `linkify.py` as interlinked hypertext. Search is fully client-side via Pagefind — no server required.

## Eleventy Configuration

`.eleventy.js` (in `site/`, run from repo root):

```js
module.exports = function(eleventyConfig) {
  eleventyConfig.addPassthroughCopy("images"); // relative to input (repo root)

  return {
    dir: {
      input: ".",              // repo root (resolved relative to cwd, which is repo root)
      output: "site/_site",
      includes: "site/_includes",
      data: "site/_data",
    }
  };
};
```

Run from repo root: `npx @11ty/eleventy --config=site/.eleventy.js`

### Article routing

`articles/articles.11tydata.js` (directory data file, committed to the repo):

```js
module.exports = {
  layout: "article.njk",   // resolved relative to site/_includes
  permalink: "/{{ page.fileSlug }}/index.html"
};
```

`site/index.njk` must include a frontmatter permalink so it outputs to the site root rather than `site/index.html`:

```yaml
---
permalink: /index.html
---
```

`page.fileSlug` for `articles/alexandre-james-henry-1848-1912.md` resolves to `alexandre-james-henry-1848-1912`. Article URLs take the form `/<slug>/`.

## Metadata Extraction (no frontmatter)

Article files have no YAML frontmatter. All metadata is extracted from the markdown content at build time. The extraction logic must be lenient with whitespace and formatting variations that exist in the current source files.

| Field | Extraction rule |
|---|---|
| **Title** | Text of the first `# ` heading line, stripped of the `# ` prefix |
| **Date range** | Match `\((\d{4}[–\-]\d*\s*)\)` on the title line; extract the inner group |
| **Category** | `"Person"` if title matches `Last, First (dates)` pattern; `"Family"` if title contains "Family"; `"Other"` for everything else (businesses, buildings, etc.) |
| **Metadata block** | All lines matching `^\*\*[^*]+:\*\*` at line start (colon is inside the bold span, matching the `**Label:**` format used throughout), collected from the top of the file skipping intervening blank lines, stopping at the first non-empty line that does NOT match the pattern. Section headings like `**Early Life**` (no colon before `**`) are excluded naturally. Rendered verbatim in the inset panel. |
| **Excerpt** | First non-empty line that does NOT start with `**` and is NOT the title, truncated to 200 characters. Lines shorter than 20 characters are skipped to avoid stray artefacts. |

**Note on source data quirks:** `alexandre-stables-at-173-east-73rd-street.md` has two malformed metadata lines: `**Location: **` (trailing space before closing `**`) and `**Built:1893**` (value concatenated inside the bold span). Neither matches `^\*\*[^*]+:\*\*`, so the stables article will have an empty metadata panel — acceptable given its atypical content. These lines should be corrected in a future `parse_docx.py` pass but are not a blocker.

## Visual Design

**Style:** Archival — warm parchment background (`#f5f0e8`), Georgia serif, deep brown headings (`#2c1810`), gold accent (`#c8a96e`), muted link colour (`#8b6340`). Dark brown navigation bar (`#2c1810`).

## Pages

### Homepage (`/`)

- Dark nav bar: site title left, tagline right.
- Centred search box powered by Pagefind UI (JS/CSS loaded from `/pagefind/pagefind-ui.js`).
- Article count rendered at build time from `articles.js` array length.
- Random article card: title, date range, excerpt, "Read article →" link, "Shuffle ↺" link.
  - Full `articles.js` manifest written into a `<script>` tag as a JSON array.
  - Inline JS picks a random entry on page load and re-picks on "Shuffle" click.

### Article page (`/<slug>/`)

**Layout:** Two-column — narrow sidebar (~200px) left, prose right.

**Sidebar:**
- "← All articles" link to `/` at top.
- **Links in this article** — `outgoinglinks[page.fileSlug]` → list of `{ title, slug }` objects.
- **Also appears in** — `backlinks[page.fileSlug]` → list of `{ title, slug }` objects.
- Both sections are omitted if the list is empty.

**Article content:**
- Small uppercase category label above the title.
- `h1` title (Last, First format) and date range in italic, separated by a horizontal rule.
- Metadata inset panel: matched `**Label:**` lines rendered with a gold left border and parchment background.
- Body prose with inline hyperlinks styled in the muted link colour (`#8b6340`).

**Nav bar** includes a compact Pagefind search input that opens the Pagefind overlay on the same page.

## Search

Pagefind runs as a post-build step: `npx pagefind --site site/_site`. It indexes all generated HTML and writes its bundle to `site/_site/pagefind/`.

Pagefind UI is initialised with `baseUrl: "/"`.

## Data Files

### `_data/backlinks.js`

Reads all `articles/*.md`, parses every `[text](/slug/)` link, and returns a map of target slug → list of sources with human-readable labels:

```js
{
  "alexandre-james-henry-1848-1912": [
    { title: "Alexandre Family", slug: "alexandre-family" },
    { title: "Alexandre Line",   slug: "alexandre-line" }
  ],
  …
}
```

Source titles are read from the `# ` heading of the source file. Keys are slugs (no `.md` extension). The template looks up `backlinks[page.fileSlug]`.

### `_data/outgoinglinks.js`

Same parse pass, inverted — per-source outgoing links:

```js
{
  "alexandre-family": [
    { title: "Alexandre, Frederick Francis (1809–1889)", slug: "alexandre-frederick-francis-1809-1889" },
    …
  ],
  …
}
```

Keys are slugs (no `.md` extension). Link titles are read from the `# ` heading of the target file.

### `_data/articles.js`

Returns the full article manifest for the homepage random picker:

```js
[
  { title: "Alexandre, James Henry", slug: "alexandre-james-henry-1848-1912", dates: "1848–1912", excerpt: "Son of Frederick Francis Alexandre…" },
  …
]
```

## Build Pipeline

### Local development

`site/package.json` scripts:

```json
{
  "scripts": {
    "build": "cd .. && npx @11ty/eleventy --config=site/.eleventy.js && npx pagefind --site site/_site",
    "serve": "cd .. && npx @11ty/eleventy --config=site/.eleventy.js --serve"
  }
}
```

Run from `site/`: `npm install && npm run build`

### GitHub Actions (`.github/workflows/deploy.yml`)

Trigger: push to `main`.

```yaml
steps:
  - uses: actions/checkout@v4
  - uses: actions/setup-node@v4
  - run: npm ci
    working-directory: site
  - run: npx @11ty/eleventy --config=site/.eleventy.js   # run from repo root
  - run: npx pagefind --site site/_site
  - uses: peaceiris/actions-gh-pages@v3
    with:
      github_token: ${{ secrets.GITHUB_TOKEN }}
      publish_dir: site/_site
```

## Deployment

The site is served from the `gh-pages` branch via GitHub Pages. A **custom domain** is assumed, so all absolute paths (`/pagefind/`, `/images/`, `/<slug>/`) resolve correctly without a subdirectory prefix. If no custom domain is configured at launch, a `pathPrefix` value must be added to `.eleventy.js` and the Pagefind initialisation call.

## Cross-Article Link Format

`linkify.py` currently writes links as `[text](filename.md)` (bare filename with `.md` extension). These would render as broken `href="filename.md"` anchors in the deployed site, since pages are served at `/<slug>/`.

Before running the Eleventy build, `linkify.py` must be updated to write links as `[text](/slug/)` instead — strip the `.md` extension, prepend `/`, append `/`. Change in `linkify.py`:

```python
# Before
link_target = target_path.name          # "alexandre-james-henry-1848-1912.md"

# After
link_target = "/" + target_path.stem + "/"   # "/alexandre-james-henry-1848-1912/"
```

This also simplifies the `_data/backlinks.js` and `_data/outgoinglinks.js` parsers, which must be updated to parse `/slug/` hrefs rather than `filename.md` hrefs.
